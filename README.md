一套源码，微信 / 抖音双平台的经典 2048、六种解压玩法与 60 个深化关卡。全部在一张上屏 Canvas 内切换，玩法说明、重开确认、胜利和结束采用同页弹层，无需页面路由。附浏览器预览入口。

## 已实现玩法

- 4×4 棋盘，初始生成两个随机数字。
- 上下左右滑动；浏览器支持方向键及 WASD。
- 相同数字合并翻倍，每个方块单次移动只能参与一次合并，分数增加合成值。
- 普通滑动只有有效移动才生成新数字；提前显示下一块（基础抽取 90% 为 2、10% 为 4），落点随机。满能量可选择配对补牌、棋盘对折或未来快递三种技能。
- 达到 2048 弹出胜利提示，可继续挑战更高数字。
- 无空位且四个方向均无法移动时结束；若仍有 3 格能量且对折能合并，可先用对折解困。
- 撤销最近一步，撤销后不能连续回退；新一次有效移动重新提供一次撤销。
- 自动保存棋盘、分数、步数、预告数字、能量、配对牌位置标记、在途快递、连续合并数和通关状态；历史最佳独立保存，撤销不降低最佳记录。存储不可用时仍可游玩，但不能保证恢复。
- 同页说明与策略：大数固定角落、沿边递减排列、保留空格、减少反向移动。随机生成机制意味着策略不能保证通关。

## 技术方案

使用无第三方依赖的 JavaScript + Canvas 2D。游戏界面不是小程序 WXML 页面或 WebView；小游戏环境直接创建上屏画布，因此一套场景即可覆盖两个宿主。

| 模块 | 职责 |
| --- | --- |
| `src/core.js` | 纯逻辑：方向映射、压缩、单次合并、计分、随机生成、结束判定、相邻配对选择、镜像对折、自动择优与快递投递 |
| `src/platform.js` | 自动选择 `wx` / `tt` / 浏览器，统一画布、屏幕信息、触摸与本地存储 |
| `src/app.js` | 单页 Canvas 绘制、点击命中、手势判断、游戏状态、同页弹层 |
| `src/relax-core.js` | 清盘关卡与连锁、收纳 / 磁吸吸附、彩砂格子模拟、染色流场、软团节点约束与碰撞 |
| `src/relax-scene.js` | 六模式入口、独立自由体验与关卡场景调度 |
| `src/challenge-data.js` | 60 个固定关卡配置和可达见证，不在运行时随机出题 |
| `src/challenge-core.js` | 石块 / 出口清盘、多形状拼合、端口磁网、彩砂色层、流体覆盖、软团装盒判定 |
| `src/challenge-scene.js` | 关卡选择、旋转 / 拖放 / 染色工具、三星、撤销、存档与按需模拟 |
| `scripts/generate-challenges.js` | 离线生成确定性关卡，用搜索检查清盘与收纳解，输出固定配置 |
| `src/skill-ui.js` | 安全区布局、技能循环提醒、合并充能反馈和局部绘制限频 |
| `src/render-budget.js` | 帧率、像素预算和持续慢帧降级 |
| `src/merge-effects.js` | 有限合并特效池、形变和轻量装饰 |
| `src/swap-effect.js` | 配对牌从原牌翻出、展示卡背、飞向标记落点的单次动效 |
| `src/feature-effects.js` | 四方向对折展开、信封寄送与拆封落牌的单次动效 |
| `game.js` / `game.json` | 双平台入口和竖屏配置 |
| `index.html` / `preview.html` | 正常浏览器游戏入口 / 满能量示例体验台；均不随小游戏上传 |
| `scripts/build.js` | 输出微信、抖音独立导入目录和各自工程配置 |

以 358 像素宽的设计坐标等比适配屏幕。原生顶部预留状态栏与胶囊空间，底部按 safeArea.bottom 预留系统手势区（至少 18px），以 780px 设计高度适配，Canvas 按设备像素比绘制（普通档上限 2，并限制总像素数）。18 屏幕像素为滑动阈值，主轴位移须超过副轴的 1.15 倍以避免对角误判；仅从棋盘区域发起的手势触发移动。手指移动越过阈值立即执行，一次触摸只执行一步，抬手不重复触发。110ms 三次缓出位移动画，输入锁定总计 200ms；合并回弹和特效尾段独立播放。动画期间只保留最新一次待执行方向，结束后按新棋盘重新计算，防止操作堆积。棋盘移动期间技能点击提示等待，暂停撤销及弹层操作。按需请求动画帧；没有可用技能与其他动画时静止停帧，技能可用时仅以 30fps 重绘底部技能区；Canvas 仅在尺寸改变时重设分辨率，降低帧间开销。当前无音效或震动。

状态流：触摸输入 → 阈值与方向判定 → 纯逻辑移动（含方块轨迹）→ 保存撤销快照 → 推进快递倒计时并尝试投递 → 若有空位按预告生成数字并抽取下一块 → 更新分数 / 能量 / 胜负 → 存档 → 移动及合并动画 → 胜负弹层或消费缓存输入。无效移动不会生成数字或覆盖撤销快照。

本地单机无需服务器。未来若增加排行榜，应将身份验证、成绩校验、反作弊放到后端，并分别接入两个平台的登录和关系链能力；不可把客户端分数当作可信数据。广告 / 分享接口应置于平台适配层，在取得真实资源 ID 后接入，避免把平台专属 API 渗入规则层。

官方技术依据：[微信 Canvas API](https://developers.weixin.qq.com/minigame/dev/api/render/canvas/wx.createCanvas.html)、[抖音小游戏开发指南](https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/develop/guide/dev-guide/bytedance-mini-game)、[抖音 Canvas API 与像素比说明](https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/develop/api/javascript-api/drawing/picture/tt-create-canvas)。

## 差异化：下一步由你掌握

本版保留经典滑动合并规则，并加入同值配对、棋盘对折、未来快递三种技能；三者共用 3 格能量，折一下自动执行，快递选址在同一场景完成。

1. **下一块预告**：提前看到即将生成的 2 / 4，帮助判断一次移动后留下的空位是否适合后续合并；不预告落点。
2. **合并蓄能、同值配对**：每次产生合并的有效移动增加 1 格能量（同一步多次合并仍只加 1），上限 3。满格点击“配对”，优先从旁边有空格的现有牌中选择较大数字，在其相邻空位补一张同值牌。消耗 3 格能量，不增加步数或分数，不改变普通下一块预告。补牌建立撤销快照，技能不收费、不看广告。满盘时提示先腾出空位，不扣能量。
3. **连续合并反馈**：连续有效移动均发生合并时显示连合次数；有效但未合并时归零，无效滑动不影响。连合只提供反馈，不改变得分规则。
4. **更直接的滑动反馈**：滑动中触发、方向锁定、缓动移动、合并弹跳、新数字缩放、单次输入缓存。实际触控手感和帧率仍需在两平台真机上验收。

策略示例：棋盘已有 64，且它旁边有空位时，技能可补一张 64，配对原牌与新牌分别标记，方便下一次滑动合并为 128。相同优先级的候选位置随机选择；不直接自动合并或发放合并分数。这里的创新是相对于本项目旧版，并不声称其他产品从未采用类似机制。

旧存档自动补齐策略字段。位置标记通过 `pairHint: {source,target,value}` 保存，读取时验证两格数字相同且相邻；无效标记丢弃。撤销恢复整个棋盘、预告、能量与配对标记，历史最佳保持。当前撤销只在运行期间保留一步，重启不会恢复撤销快照。

## 合并反馈与性能预算

合并采用沿滑动方向挤压 → 接触后停留 24ms → 78ms 达到回弹峰值 → 340ms 复位。单块形变通过互为倒数的横纵缩放近似保持面积，圆角、高光和浅阴影同步变化，数字独立绘制以保持清晰。全部使用 Canvas 2D 路径，不引入 3D 物理、全屏流体、模糊滤镜、额外纹理或持续运动的背景。

### 运行预算

| 项目 | 普通档 | 省电档 |
| --- | --- | --- |
| 动画绘制目标上限 | 60fps | 30fps |
| 画布 DPR 上限 | 2 | 1.5 |
| 画布总像素预算 | 200 万 | 120 万 |
| 同时绘制装饰的合并位置 | 最多 4 处 | 最多 2 处 |
| 每处液滴数 | 4 | 0 |
| 碰撞后特效尾段 | 420ms | 340ms |
| 基本反馈 | 方向挤压、回弹、圆角、高光、数字 | 同左 |

DPR 同时受设备实际像素比、档位上限、总像素预算约束。DPR 3 的手机在其他条件相同时改为 DPR 2，画布像素数约减少 56%；这是像素数量计算，不代表实测功耗下降 56%。

- 只在输入、界面变化或动画存活时绘制；无可用技能时静止无常驻 RAF / 定时器；可用技能循环提醒仅以 30fps 局部绘制，不新增循环定时器；技能提示仅保留一个用于清除文字的一次性定时器。移动仍为 110ms，200ms 后解锁输入，特效尾段不阻塞下一步。
- 高刷新率设备通过时间预算限制绘制；宿主支持 `setPreferredFramesPerSecond` 时同步设置目标帧率，不支持则使用绘制限频。按时间计算动画，不通过增加帧数改变速度。低刷新率屏幕按可用回调绘制，不能保证每台设备达到目标帧率。
- 每 24 个实际绘制帧评估一次：其中至少 12 帧 JS 绘制耗时达到 8ms，或相邻 RAF 回调间隔超过 25ms 且小于 100ms，切至省电档。本次会话不自动升档，避免反复切换。该监测是负载信号，不能直接测量 GPU 耗时、电池功率或温度。
- 形变池最多保留 8 组合并，装饰单独限量；不因连击增加粒子数量。粒子方向在创建时计算，过期特效原地清理，不堆积历史轨迹。旧的三层背景光晕已移除。
- 设备信息仅在启动、窗口尺寸变化、回前台时读取。画布只在尺寸或画质档位改变时重设分辨率。
- 切后台清空手势与缓存方向、结束视觉动画、取消帧请求并存档；回前台直接绘制已提交的棋盘，不补播动画。即使旧回调迟到也不会重启后台渲染。合出 2048 时切后台仍会保留胜利弹层。
- 浏览器遵循系统“减少动态效果”，关闭粒子、拖影与弹性变形。当前不播放音效、不触发震动。

## 蓄能配对：同值牌与明确落点

### 选牌与位置算法

`core.pair(board)` 只在点击时检查最多 16 格，每格检查上下左右 4 个邻居，最多 64 次邻接检查，不在动画帧中搜索或模拟棋盘。选择旁边有空位的最大数字；同等候选间随机选择一组原牌 / 目标空格。原牌保留，目标格此前必须为空，不跨行、不覆盖已有数字。

点击前记录完整撤销快照，随后写入目标数字、`pairHint` 和能量消耗并存档，不增加步数、得分或连续合并数，不改变普通下一块。UI 在翻牌结束前隐藏新牌正面的静态绘制，显示“落点”；动效从原牌位置翻出，最后准确落入目标格。切后台直接结束动画，已补入的牌及标记保留，不会丢牌或重复补牌。

### 动效与标记

- 按钮满格显示“配对 3/3 +”，播放时显示“补牌中 ⇄”。不足时说明还差几格，移动窗口内提示稍后再配对。
- 原牌用绿框和“配对原牌”标记，目标格用金框和“落点 / 新牌”标记。文字明确说明数字与第几行第几列，例如“配对牌 64 → 第2行第4列”。
- 一张配对牌从原牌位置放大到棋盘中央，翻至独立深绿卡背，再翻出同值数字，最后落到指定空格。时序为 0～150ms 抬起放大、150～310ms 翻至卡背、310～380ms 展示卡背、380～540ms 翻出数字、540～720ms 飞向目标格。
- 简短文字保留 1.6 秒；清除后仍显示新牌位置。原牌 / 新牌标记静态保留到下一次有效滑动，无效滑动不会清除。撤销 / 新局恢复或清理相应标记。
- 翻牌期间仅缓存最后一个滑动方向，720ms 后执行；普通棋盘移动仍按原 200ms 节奏解锁。重复点技能不重复扣能量；后台不补播或执行旧缓存方向。
- 纯 Canvas 2D，只有一张动效牌，无物理求解、模糊或循环粒子。复用 60fps / 30fps 预算，技能已消耗且动画结束时停帧；静态位置框不循环闪烁。系统减少动态效果时直接显示补牌结果和标记。

## 新玩法一：折一下

入口在底部「折一下」，副文案「自动择优合并」。满能量后单击立即选择收益最高的方向并执行，消耗 3 格充能，无需选择方向或再次确认。没有可合并组合时提示原因，不消耗充能，也不修改撤销快照。

`bestFold` 只在点击时评估左、右、上、下四个方案，每个方案最多检查 8 对。优先比较本次实际总得分（包含已到期快递在对折后签收产生的合并分），同分时优先合并组数更多，再优先最终空格更多；仍相同时按左、右、上、下固定顺序选择，避免随机跳变。这里优化的是当前一步收益，不搜索后续局面或承诺全局最优通关策略；不增加逐帧策略计算。

以向左折为例，右半盘沿中线映到左半盘：每行第 4 列对应第 1 列，第 3 列对应第 2 列。只有两个非空且相同的数字才合并，目标翻倍、来源清空；不同值、空格组合保持原位。向右、向上、向下按镜像对称处理。每次最多检查 8 对，每牌最多参与一次，数字总和守恒。

例如一行 `2,4,4,2` 向左折后变为 `4,8,0,0`，得 12 分。对折记 1 步，不额外生成普通 2 / 4，不改变下一块预告，不返还能量，也不推进快递倒计时；已到期的快递可以在对折腾出的收件格签收。满盘无法普通移动时，满能量且有可折合并的方向仍允许使用技能。

动画为 680ms 的半盘抬起 → 侧面收窄 → 卡背压合 → 展开，360ms 压合处更新合并画面，再接有限合并回弹；普通档尾段约到 780ms 结束。旋转通过 Canvas 2D 坐标缩放模拟，只有半盘和最多 16 个数字，没有三维场景或物理求解。动画期间只保留最新滑动，展开结束后执行。撤销恢复整个技能前状态，切后台直接显示已提交结果。

## 新玩法二：未来快递

入口在底部「未来快递 · 3」。默认选中当前最大数字，也可点其他原牌切换数字，再点空格确定地址。确认消耗 3 格能量，将该数字的副本寄出，原牌保留；寄出不增加分数或步数，不修改普通下一块预告。最多同时存在一封在途快递。

- 金框明确显示收件位置、数字和剩余步数；只在后续有效普通滑动后从 2 减至 1、再减至 0，无效滑动、等待、切后台和技能操作不减少倒计时。
- 地址是固定格子，其他牌仍可滑入。到期时为空则落牌，同值则立即合并并按合成值计分，异值则显示「待签收」，之后有效滑动或对折腾出该格再投递；不覆盖原牌、不擅自换地址。
- 每次普通滑动先完成移动，再推进 / 投递快递，最后生成普通预告牌；若快递占满最后一个空格，本步跳过普通生成，下一块预告保留。快递本身合并不额外蓄能，防止技能循环。
- 寄出使用 500ms 弧线信封飞行；签收在普通位移 110ms 后播放 420ms 开信封、数字浮起与落牌。签收结束前缓存最近一个滑动方向。全部只有一个信封和一张数字牌，不叠加循环粒子；浏览器减少动态效果时直接显示结果。
- `parcel: {value,target,remaining}` 随存档保存，读取校验数字、位置和剩余步数。撤销寄出恢复能量，撤销移动恢复当时棋盘和倒计时；切后台不重复送达，不用墙上时间自动结算。

策略示例：寄一张 64 到右下角，用两次滑动让另一张 64 到达同一格，到期合成 128；也可以把收件位置保持为空，用两步换取一张可规划落点的同值牌。预期落点可能被普通随机生成占用，需为签收留出位置。

### 从合并到充能的明确反馈

每次**有效滑动发生至少一次合并**，充能增加一格；同次滑动合并多组仍只增加一格，无效滑动、没有合并的滑动不增加。正常位移完成后，一个金色「+1」从合并位置飞入充能槽当前进度末端；槽内以平滑缓动从旧进度增长至新进度，不再显示 1 / 2 / 3 或勾选。状态文字同时显示「合并充能 +1 · N/3，还差 N 次合并」。满格后可选一个技能，使用后清空充能槽，快递选址 / 取消不消耗，折一下点击即执行并扣除。充能不是每滑动三步自动获得。

充能飞行 / 填充反馈共 560ms，前置 110ms 普通位移，始终只有一个提示，后一次有效移动替换旧提示；不延长原有 200ms 输入窗口。使用技能、撤销、新局、切后台会清理旧提示。浏览器减少动态效果时不播放飞行，直接更新充能槽、数字与规则说明。撤销和存档规则保持不变。

### 技能可用提醒与性能

配对可用时为苔绿、折一下为灰蓝、未来快递为暖沙，不可用时浅色；可用性按实际棋盘 / 能量条件判断。各按钮满足自身条件后，显示一条沿圆角边缘顺时针绕行的渐隐细线，5000ms 一圈（由 3.2 秒放慢为 5 秒）。配对使用灰绿线、折一下使用灰蓝线、快递使用低饱和铜色线，颜色与各卡协调；从尾到头仅渐变透明度，不单独绘制白色亮点或光晕，线宽固定 1.7 设计像素，最高透明度低于 0.66。三个按钮错开三分之一圈，避免同步闪动；取消整面呼吸亮度，按钮几何位置、尺寸和文案保持固定。普通滑动不重置相位，消耗充能或失去使用资格后立即停止。选择面板或其他弹层打开时暂停，关闭后继续；后台停帧，回前台恢复。视觉运动不改变点击范围。

边缘轨迹在初始化时缓存 256 个点，逐帧只插值位置；每个按钮固定 12 次短线描边、0 次光点填充，不使用模糊、阴影、渐变或粒子池。减少动态效果时仅保留静态可用配色。空闲循环上限 **30fps，仅重绘面板内 346×77 设计像素的三个技能卡区域**，不反复绘制棋盘、分数或充能标题，不重复注册按钮。充能飞入等短动画使用原有 60/30fps 预算，不新增循环定时器、模糊、纹理或额外画布。慢帧降级立即调整分辨率并完整重绘，避免局部区域错位；技能可用性按状态缓存，奖励状态按事件读取。

**操作与成绩**：离散玩法每次有效操作后检查；模拟玩法点击「检查」确认。彩砂未落稳、软团尚在松手跟随时会等待后再检查。通关后冻结模拟、显示星级，可撤销、重玩或下一关。清盘单次连合最多 8 轮；收纳物件卡整张可点击 / 拖动，选中旋转不会因再次抓取而丢失朝向。软团从托盘抓起后才受重力，松手保留最多 320ms 跟随，完整放入会安放，重新抓取可调整；盒壁做节点扫掠检测，长软团使用轮廓碰撞而非大圆占位。

**三星规则**：完成目标至少一星；达到关卡效率目标二星；同时本次不撤销得三星。清盘 / 收纳 / 磁网 / 软团按有效操作次数，彩砂按实际材料消耗（目标量的 115% 内），流体按颜料消耗（配额的 80% 内）。重玩不会降低历史星级和最佳效率。每关底部说明三星条件，清盘另显示参考步数。

**进度与恢复**：新命名空间 `2048-challenges-v1` 保存各关最高星级、最佳效率、每种玩法所选关；清盘 / 收纳 / 磁网分别保存最近一个局面，回列表、切换模式、重启后可继续。恢复校验石块、数值、形状、重叠、端口类型与固定端点。离散玩法最多保留 12 次撤销，模拟玩法最多 3 个检查点，撤销历史只在本次关卡有效。模拟数组不逐帧写入本地，退出该关或重新加载会重建材料；已获成绩保留。经典 `2048-save` 与早期自由体验 `2048-relax-v1` 独立保留。

**性能**：模拟最多 30 次更新 / 秒；高频移动只缓存最新输入，在帧回调消费。彩砂固定 84×104、最多 2200 粒；流体固定 40×48，复用一次创建的小尺寸离屏缓存；闯关软团最多 6×10 节点，每帧最多两步、每步三轮约束。隐藏场景、暂停、通关后停止计算；回前台重置时钟，不追赶离开时长。复用原有分辨率与帧率降档。这些是资源上限与调度约束，不等于手机温升已验收。

### 自由体验的状态与存档

- 三种目标玩法分别保存到 `2048-relax-v1`：清盘的关卡 / 棋盘、收纳的已放置编号、磁吸的已归位编号。恢复时校验关卡范围、数组、数字、编号和重复值；坏数据回到对应初始状态。
- 三种模拟模式仅在本次运行内保留；切回列表再进入可以继续，重新加载后重建。彩砂 / 流体 / 软团不逐帧写存储。
- 每种目标玩法保留一步独立撤销，撤销历史仅在本次运行内有效；模式重置不改经典 2048。存档不会保存正在执行的拖拽或中间动画，切后台保留已经提交的落位与清盘结果。
- 暂停会停止模拟与帧任务；切后台取消指针和帧任务，回前台重置时钟，不按离开时长追赶计算。返回列表后不继续模拟隐藏模式。

### 数值模拟与性能预算

彩砂使用 84×104 的固定格子，两个 `Uint8Array` 保存砂和墙；每步最多三次由下向上的扫描，不分配 2200 个物理刚体。砂粒不会穿墙或互相覆盖，静止后停帧。

流体使用 40×48 网格的速度场与三路染色，半拉格朗日平流、6 次压力迭代与速度衰减；这是带染色的二维流场，不是三维自由表面水体。核心 13 个浮点数组共 99,840 字节，尺寸不会随触摸次数增长。浏览器以一个 40×48 的离屏缓存绘制并平滑放大；小游戏在主画布之后创建小尺寸离屏画布，不依赖 DOM 或小程序组件 API。离屏不可用时只尝试一次，再回退到分档色块绘制。[抖音小游戏 createCanvas 文档](https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/develop/api/javascript-api/drawing/picture/tt-create-canvas) 说明首次创建上屏画布、之后创建离屏画布。

软团固定为 12×10 = 120 个节点，采用 Verlet 积分、边长与面积恢复约束；碰撞先做中心距离筛选，再对接触节点做近似投影。它是可变形的二维软团，不是完整有限元材料求解。每次显示帧最多两步固定积分，每步最多三次约束迭代。无拖拽时满足静止条件或累计 600 个积分步（约 10 秒）后休眠，重新抓取才唤醒；无需持续计算微小接触抖动。

三种模拟模式最多 30 次更新 / 秒；高频触摸只更新输入并合并到帧回调，不直接重复绘制流体全画面。只模拟当前模式，无追赶大循环。继续复用 60→30fps、DPR 2→1.5 与总像素限制的单向降档；三种目标玩法静止时停帧。减弱动态效果时清盘和吸附直接显示结果，自由模拟仍可手动暂停。当前没有新增声音或震动。
