# 2048合成大师

一套源码，微信 / 抖音双平台的经典 2048 小游戏。单个 Canvas 游戏场景，玩法说明、重开确认、胜利和结束均采用同页弹层，无需页面路由。附浏览器预览入口。

## 名字与定位

推荐名称：**2048合成大师**。2048 放在开头，紧接“合成”玩法关键词，最后用“大师”形成记忆点。备选：2048数字合成、2048天天合成。宣传文案：**滑动一下，合成快乐。**

搜索关键词建议：2048、合成、数字、经典、益智、滑动。名称与介绍自然描述玩法，不堆砌关键词。以上是命名策略，尚无平台关键词搜索量数据，不能保证流量；正式提交前在两个平台检查重名与名称可用性。

## 已实现玩法

- 4×4 棋盘，初始生成两个随机数字。
- 上下左右滑动；浏览器支持方向键及 WASD。
- 相同数字合并翻倍，每个方块单次移动只能参与一次合并，分数增加合成值。
- 只有有效移动才生成新数字；提前显示下一块（基础抽取 90% 为 2、10% 为 4），落点随机。
- 达到 2048 弹出胜利提示，可继续挑战更高数字。
- 无空位且四个方向均无法移动时结束。
- 撤销最近一步，撤销后不能连续回退；新一次有效移动重新提供一次撤销。
- 自动保存棋盘、分数、步数、预告数字、能量、连续合并数和通关状态；历史最佳独立保存，撤销不降低最佳记录。存储不可用时仍可游玩，但不能保证恢复。
- 同页说明与策略：大数固定角落、沿边递减排列、保留空格、减少反向移动。随机生成机制意味着策略不能保证通关。

## 技术方案

使用无第三方依赖的 JavaScript + Canvas 2D。游戏界面不是小程序 WXML 页面或 WebView；小游戏环境直接创建上屏画布，因此一套场景即可覆盖两个宿主。

| 模块 | 职责 |
| --- | --- |
| `src/core.js` | 纯逻辑：方向映射、压缩、单次合并、计分、随机生成、结束判定 |
| `src/platform.js` | 自动选择 `wx` / `tt` / 浏览器，统一画布、屏幕信息、触摸与本地存储 |
| `src/app.js` | 单页 Canvas 绘制、点击命中、手势判断、游戏状态、同页弹层 |
| `game.js` / `game.json` | 双平台入口和竖屏配置 |
| `index.html` | 浏览器预览，共享相同渲染与游戏逻辑 |
| `scripts/build.js` | 输出微信、抖音独立导入目录和各自工程配置 |

以 358 像素宽的设计坐标等比适配屏幕。原生顶部预留状态栏与胶囊空间，Canvas 按设备像素比绘制（上限 3）。18 屏幕像素为滑动阈值，主轴位移须超过副轴的 1.15 倍以避免对角误判；仅从棋盘区域发起的手势触发移动。手指移动越过阈值立即执行，一次触摸只执行一步，抬手不重复触发。110ms 三次缓出位移动画 + 90ms 合并弹跳 / 新生缩放，总计 200ms。动画期间只保留最新一次待执行方向，结束后按新棋盘重新计算，防止操作堆积。动画期间暂停换牌、撤销及弹层按钮。按需请求动画帧，静止时不持续重绘；Canvas 仅在尺寸改变时重设分辨率，降低帧间开销。当前无音效或震动。

状态流：触摸输入 → 阈值与方向判定 → 纯逻辑移动（含方块轨迹）→ 保存撤销快照 → 按预告生成数字并抽取下一块 → 更新分数 / 能量 / 胜负 → 存档 → 移动及合并动画 → 胜负弹层或消费缓存输入。无效移动不会生成数字或覆盖撤销快照。

本地单机无需服务器。未来若增加排行榜，应将身份验证、成绩校验、反作弊放到后端，并分别接入两个平台的登录和关系链能力；不可把客户端分数当作可信数据。广告 / 分享接口应置于平台适配层，在取得真实资源 ID 后接入，避免把平台专属 API 渗入规则层。

官方技术依据：[微信 Canvas API](https://developers.weixin.qq.com/minigame/dev/api/render/canvas/wx.createCanvas.html)、[抖音小游戏开发指南](https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/develop/guide/dev-guide/bytedance-mini-game)、[抖音 Canvas API 与像素比说明](https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/develop/api/javascript-api/drawing/picture/tt-create-canvas)。

## 本地预览与测试

```sh
npm test
npm run build
npm run dev
```

浏览器访问 http://localhost:8080 。手机可在同一局域网访问开发电脑的 IP:8080。

## 微信与抖音导入

1. 执行 `npm run build`。
2. 微信开发者工具以小游戏类型导入 `dist/wechat`；默认 `touristappid` 为本地游客预览占位，上传前替换为真实小游戏 AppID。
3. 抖音小游戏开发者工具导入 `dist/douyin`，填写真实 AppID；空 AppID 不可用于发布。
4. 修改应在 `src` 中完成，再次构建覆盖产物。避免直接修改 dist 中代码。
5. 各自执行真机预览和上传审核。两平台分别注册、分别配置、分别发布，共享源代码不等于一次发布到两个平台。

正式发布前需完成：真实 AppID、平台名称可用性确认、图标 / 截图 / 类目 / 资质与隐私说明配置，并用两平台工具验证触摸、刘海屏 / 胶囊 / 底部安全区、切后台恢复和本地存档。浏览器预览不能代替宿主验证。

## 差异化：下一步由你掌握

本版把策略信息放到棋盘上方，不增加页面或改变经典合并规则。

1. **下一块预告**：提前看到即将生成的 2 / 4，帮助判断一次移动后留下的空位是否适合后续合并；不预告落点。
2. **合并蓄能、主动换牌**：每次产生合并的有效移动增加 1 格能量（同一步多次合并仍只加 1），上限 3。满格后可将预告 2 切为 4，或 4 切为 2，消耗全部能量，不增加步数、不移动棋盘。换牌也建立撤销快照。技能不收费、不看广告。
3. **连续合并反馈**：连续有效移动均发生合并时显示连合次数；有效但未合并时归零，无效滑动不影响。连合只提供反馈，不改变得分规则。
4. **更直接的滑动反馈**：滑动中触发、方向锁定、缓动移动、合并弹跳、新数字缩放、单次输入缓存。实际触控手感和帧率仍需在两平台真机上验收。

策略示例：下一块是 4，但棋盘主要是等待配对的 2 时，可消耗能量切换为 2；若准备累积 4，则保留预告。能量来自合并，玩家需要在当前棋盘与下一块之间作取舍。这里的创新是相对于本项目上一版，并不声称其他 2048 产品从未采用类似机制。

旧存档读取时自动补齐策略字段，保持原棋盘。撤销恢复预告、能量与连合状态，历史最佳保持。当前撤销只在运行期间保留一步，重启不会恢复撤销快照。
